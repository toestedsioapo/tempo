# Milestone 4 — Schema, agent skill, examples, README: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** make Tempo usable by agents and by someone who has never seen the repo: the JSON Schema ships with the package and every example validates against it, `SKILL.md` teaches an agent to drive the CLI, `examples/` holds the demo and an importable n8n workflow, and the README demo is a test, not prose.

**Architecture:** no engine change. Core and CLI source stay as they are (a defect found by Task 1 is the only exception, and it gets its own A-row and branch). New artefacts are data and docs (`examples/`, `SKILL.md`, `README.md`), each pinned by a repo-level test so it cannot drift: examples are validated with ajv against the generated schema, `SKILL.md` and the README are parsed for fenced blocks and every block is run through `main` with a fake `Env`, and the n8n workflow is checked structurally and by running its command against the real binary.

**Tech Stack:** unchanged (Vitest, ajv already a core devDependency, `tsx`). No new runtime dependency anywhere (ADR rule in CLAUDE.md).

**Spec:** `ROADMAP.md` §M4 (lines 142–157, plus the M3 by-hand note at line 138); `TEST_PLAN.md` CORE-41, CLI-19, CFG-08, CFG-09, DOC-03; `DECISIONS.md` D14, D16, F21; `SPEC.md` §5; `ASSUMPTIONS.md` A-13, A-36, A-81.

## Global Constraints

- M1–M3 constraints still bind: `strict` + `noUncheckedIndexedAccess`; ESM `NodeNext` with `.js` imports; Node `>=24`; no secrets; no `npm publish`, no release; Windows PowerShell is the owner's platform and every test runs on `windows-latest` and `ubuntu-latest`.
- **Exit codes and JSON output shape are public API (D14).** Docs quote them exactly: `0` computation succeeded, `1` only with `--exit-code` and `counter_offer`, `2` input error, `3` ambiguous zone, `4` internal error.
- `schema/rules.schema.json` is generated; never hand-edited. Examples are hand-written inputs; expected outputs are produced by the CLI and committed only after reading them.
- Examples and docs are ASCII except text that is the point of the example (a non-ASCII `partyId` used to demonstrate encoding). Files are LF (`.gitattributes` gets `*.md text eol=lf` and `examples/** text eol=lf` if missing) so byte-exact comparisons hold on Windows.
- Docs never claim a thing a test did not run. The package is **not published**; any command a reader copy-pastes must work from a clone today (A-82).
- One branch per task: `m4/t01-…` … `m4/t07-closeout`. Task close-out runs `pnpm typecheck`, `pnpm lint`, `pnpm test`, `pnpm build` from the root, then `superpowers:requesting-code-review`, then `git merge --no-ff` into local `main`. Test first, Conventional Commits with the `Co-Authored-By` line from the session. Nothing is pushed until the Task 7 gate.
- Judgment calls not listed here are A-rows (next free number: **A-82**), not questions.

## Review Focus

Inputs the spec implies but no CLI-nn / CFG-nn row names; each has a test in the owning task.

1. **PowerShell 5.1 piping** re-encodes non-ASCII before the process sees it (`Get-Content f.json | tempo` without `-Encoding UTF8` turns `Zoë` into `ZoÃ«`). The README and `SKILL.md` must steer to file input / `-Encoding UTF8` / `<` redirection, and a test fails if a PowerShell pipe example for non-ASCII input omits it (Task 4, Task 6).
2. **Example drift:** an example that stops validating, or a demo whose committed output differs by one byte from the CLI's, must fail CI, not mislead a reader (Task 3, Task 6).
3. **Schema reachable from the installed package:** a consumer cannot see `schema/` at the repo root; the published tarball must contain it (Task 2).
4. **Error branches in the n8n flow:** exit `2` / `3` make an Execute Command node fail; the workflow must route them to an error branch instead of silently stopping, and `counter_offer` (exit `0` without `--exit-code`) must not be treated as an error (Task 5).
5. **Copy-paste hazards on Windows:** README snippets that need a `\` line continuation, single-quoted JSON, `export`, or `cat`; and `tempo` not being on `PATH` before a release (Task 6).

**Interfaces — the flow (left to right):**
1. `Manual Trigger` (stands in for the original Gemini-extraction node; the README says where that node plugs in).
2. `Settings` (Set, one node, edited once by the operator): `tempoRequestPath` = an **absolute path under n8n's allowed file folder** (`~/.n8n-files`, `N8N_RESTRICT_FILE_ACCESS_TO`); Windows default `C:\Users\<you>\.n8n-files\tempo-request.json`, Linux default `/home/<you>/.n8n-files/tempo-request.json` (A-83: a file, not shell interpolation, and not `/tmp`, which n8n refuses and Windows lacks); and `tempoCommand` = `tempo` (or `node C:\path\to\packages\cli\dist\bin.js` from a clone). Execute Command spawns with `shell: true` and cwd = n8n's cwd (`cmd.exe` on Windows), so paths are absolute.
3. `Build request` (Set): the full `NegotiationRequest` as one JSON string field `requestJson`, defaulting to `examples/demo.json` (single source of truth; the test enforces equality). `Write request file` (Convert to File `convertToFile` → Read/Write Files from Disk `readWriteFile`) writes it to `{{ $('Settings').item.json.tempoRequestPath }}`.
4. `Tempo check` (Execute Command, `n8n-nodes-base.executeCommand` typeVersion 1): command `{{ tempoCommand }} check "{{ tempoRequestPath }}" --json` (double quotes work in both `cmd.exe` and `sh`); **On Error: Continue (using error output)**. Verified-by-owner facts (n8n 2.38.7): this node is in `nodes.exclude` by default (security: it runs arbitrary shell commands on the host) and is enabled with `NODES_EXCLUDE=[]`; node versions available are `readWriteFile` [1, 1.1], `If` [2..2.3], `Switch` [3..3.4], `convertToFile` [1, 1.1].
5. `Parse result` (Edit Fields): `result = {{ JSON.parse($json.stdout) }}`.
6. `Decision?` (Switch or IF): `book` → `Book slot` (NoOp placeholder, where Calendar plugs in); `counter_offer` → `Offer alternatives` (NoOp; `{{ $json.result.slots }}` is the payload); error output of step 4 → `Report input error` (NoOp; reads `{{ JSON.parse($json.stdout).error.code }}`, `AMBIGUOUS_ZONE` carries `error.details`).
- `exit 0` for `counter_offer` is deliberate (D14): the flow branches on `decision`, never on the exit code, so no `--exit-code` flag.
