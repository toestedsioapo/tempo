# Milestone 3 — CLI (`tempo check | suggest | explain`): Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** the `tempo` binary: three commands over the finished core, JSON in (file, stdin or `-`) and JSON out (`--json`) or human text, `--now`, `--exit-code`, exit codes 0–4 (D14, G24), safe on Windows (BOM, UTF-16, CRLF, spaces in paths, closed pipes).

**Architecture:** `main(argv, env)` is a pure function of its arguments and an injected `Env` (ARCHITECTURE §3), so every behaviour is tested without spawning a process. Small modules, one job each: `args.ts` (argv → a parsed command or a usage error), `io.ts` (bytes → text → JSON, BOM and encoding), `now.ts` (the `--now` precedence), `clock.ts` (the only reader of the system clock), `render.ts` (JSON and human output), `main.ts` (wiring, exit codes, last-resort guard), `bin.ts` (the real `Env`, the only file that touches `process`). A few spawned-process tests on the real entry point cover what injection cannot (CLI-18).

**Tech Stack:** unchanged. Argument parsing is `node:util` `parseArgs` (ARCHITECTURE §1: no new dependency). Runtime dependencies of the CLI stay exactly `@marvinliem/tempo-core`.

**Spec:** `SPEC.md` §5 (CLI contract), §3.4 (error table), §4.9 and every `CLI exit code` line in §6; `ROADMAP.md` §M3; `TEST_PLAN.md` CLI-01 … CLI-18 (CLI-19 is M4); `ARCHITECTURE.md` §2, §3, ADR 3, ADR 7; `DECISIONS.md` D13, D14, G24, G25, G26; `ASSUMPTIONS.md` A-13, A-17, A-35, A-44.

## Global Constraints

- M1/M2 constraints still bind: `strict` + `noUncheckedIndexedAccess`; ESM `NodeNext` with `.js` imports; Node `>=24`; the CLI's only runtime dependency is `@marvinliem/tempo-core` (no argument-parser package); no secrets; no release, no `npm publish`.
- **Core is not modified.** If a task seems to need a core change, stop and record an A-row instead.
- **Exit codes and JSON output shape are public API (D14).** `0` computation succeeded, whatever the decision; `1` only with `--exit-code` and `decision === "counter_offer"`; `2` input error (`INVALID_INPUT`, `INVALID_ZONE`, `INVALID_INTERVAL`, `DST_*_LOCAL_TIME`); `3` `AMBIGUOUS_ZONE`; `4` `INTERNAL_ERROR`. The mapping already exists as `exitCodeForError` in `exit-codes.ts` and is reused, not reimplemented.
- `--exit-code` never changes output, only the status, and only for a successful computation.
- `--now` > `options.now` in the input > the real clock (ADR 3, A-13). Only `clock.ts` reads the clock (CLI-10). `now` is a whole-second `…Z` string (A-17).
- Input is UTF-8; a leading BOM is stripped. No interactive prompt, ever; no waiting on a TTY (CLI-13).
- With `--json`, every outcome including errors is one JSON document on stdout and nothing on stderr. Without it, errors are one line on stderr and stdout stays empty.
- Human-readable text is **not** public API (A-13); it is pinned by snapshots only. It is **ASCII-only** (`->`, never an arrow character): Windows PowerShell 5.1 consoles show non-ASCII as mojibake. This covers `renderHuman`, `helpText()` and every message the CLI itself writes; text copied from the input (a non-ASCII `partyId`, a path) is exempt.
- Never call `process.exit()` (it can truncate piped output on Windows); `bin.ts` sets `process.exitCode`.
- Coverage ≥ 95 % lines and branches for `packages/cli/src` (QG-01), `bin.ts` and the barrel excluded like core's `index.ts` (A-70 style).
- Windows (PowerShell) is the owner's platform; every test and script runs on `windows-latest` and `ubuntu-latest`.

## Review Focus

Inputs the spec implies but no CLI-nn row names; each has a test in the owning task.

1. **PowerShell 5.1 files.** `>` and `Out-File` write UTF-16 LE with a BOM; `Set-Content -Encoding utf8` writes UTF-8 with a BOM. Both must be accepted, and a UTF-8 file with a stray invalid byte must be `INVALID_INPUT`, never mojibake (Task 1).
2. **Valid JSON that is not an object** (`null`, `[]`, `42`, `"x"`, empty file, empty stdin) with and without `--now`: `INVALID_INPUT`, exit 2, never a crash from injecting `now` (Task 2, Task 4).
3. **Closed stdout** (`tempo explain f | head -1`, EPIPE) and large output: no stack trace, exit status intact, output not truncated when the consumer reads it all (Task 6).
4. **Bad `--now`**: fractional seconds, an offset (`+02:00`), lowercase `z`, a date only, given twice, or `--now` with no value: exit 2 and a message that names the flag (Task 3, Task 4).
5. **Odd paths and text**: path with spaces and non-ASCII characters, a directory instead of a file (`EISDIR`), `-` mixed with a second file, a non-ASCII `partyId` echoed in output, CRLF input, JSON output without BOM (Task 1, Task 4, Task 6).

## Decisions made in this plan (each becomes an `A-nn` row in the task that implements it)

- **A-73** (Task 3): `node:util` `parseArgs` with `strict: true`; a thrown parse error becomes a usage error (exit 2). The only short flag is `-h` (alias of `--help`); `-` alone means stdin. A flag repeated, or a second positional, is a usage error.
- **A-74** (Task 1): `Env.readStdin()` and `Env.readFile()` return `Uint8Array`, not `string` as ARCHITECTURE §3 sketches, so BOM and encoding handling live in tested code. `Env` also gains `stdinIsTTY: boolean` and `version: string`. Accepted encodings: UTF-8 (BOM optional) and UTF-16 LE/BE **with** a BOM (PowerShell 5.1 `>`); BOM-less UTF-16 is not sniffed and fails as `INVALID_INPUT`. Decoding is fatal on invalid sequences.
- **A-75** (Task 2): `--now` injection. If the parsed input is a plain object and `options` is absent, `options: { now }` is added; if `options` is a plain object without a `now` key, `now` is added; in every other case the input passes to core unchanged and core reports the error. A `now` key that is present (even `null`) is never overwritten by the clock, only by `--now`. The clock is called only when needed.
- **A-76** (Task 4): CLI-originated failures (unreadable path, bad JSON, bad encoding, usage error, empty input, a TTY with no input) are `INVALID_INPUT` `ErrorResult`s with `details: { source: "file" | "stdin" | "argv", … }`; an unexpected exception inside `main` is `INTERNAL_ERROR` (SPEC §3.4 already allows both).
- **A-77** (Task 4): `--json` output is `JSON.stringify(result, null, 2) + "\n"`; human error line is `tempo: <CODE>: <message>` with newlines collapsed to spaces. `main` with no command prints usage to stderr and exits 2; `--help` and `--version` print to stdout and exit 0, also after a command (`tempo check --help`).
- **A-78** (Task 4): `commands.ts` replaces ARCHITECTURE's `commands/{check,suggest,explain}.ts` — each command is one line (`evaluate` / `suggest` / `explain`), three files would only restate imports.
- **A-79** (Task 6): spawned-process tests run `bin.ts` through `tsx` (resolved from the repo root) with `cwd = packages/cli`, so they need no build and cannot test a stale `dist`; CI additionally smoke-runs the built `dist/bin.js --version` after `pnpm build`.

## Execution conventions

- One branch per task: `m3/t01-io` … `m3/t07-closeout`. Task close-out runs `pnpm typecheck`, `pnpm lint`, `pnpm test`, `pnpm build` (all four, from the repo root, on the branch), then a review (`superpowers:requesting-code-review`), then `git merge --no-ff` into local `main`.
- Test first, always: write the test, run it, watch it fail for the right reason, then implement. Commits are Conventional Commits ending with the `Co-Authored-By` line from the session.
- Nothing is pushed until the Task 7 gate. Judgment calls not listed above are recorded as A-nn rows (next free number: A-80), not asked.
- Unit tests import `main` and fakes; the fake `Env` lives in `packages/cli/test/env.ts` (Task 1) and is the only way tests build an `Env`.
